Make sure you've completed the [datagen setup](./setup) process first.

The creation of Dimensions is broken down into 2 parts:

- **DimensionType**: This defines the features of the dimension. i.e, hasFixedTime, hasSkyLight, minY, etc.
- **Level Stem (Dimension)**: This defines the biomes, noise settings and dimensionType.

::: info INFO

A dimension may or may not have a custom biome. i.e, the user can choose to have singular or multiple vanilla biome.

:::

### Advanced Configuration {#advanced-configuration}

This section will be dedicated to custom NoiseGenerator, Biome Sources and Noise Settings. If you are satisfied with the configuration done in [Stem Customization](#stem-customization), you may skip this section to [Registering Level Stem](#registering-level-stem).

From this point on we will also be looking at the JSON structure of the configurations as knowing the exact structure produced by the datagen code will help you to verify output, debug mismatches, and make safe modification.

Now that said, we will take a look at the JSON structure of the Dimension Stem.

```Text
Root tag
├── type : The dimension type that we used (i.e EXAMPLE_DIMENSION_TYPE).
└── generator : Generation settings used for the dimension.
    ├── type : The generator type. One of noise, flat, or debug.
    └── settings : settings of the generators described below ...
```

Before continuing it is recommended to make the following changes to the code in [Stem Customization](#stem-customization) to make it easier to read and understand.

#### Generator {#generator}

Now we will take a look at the available generator types.

##### Debug {#debug}

This generator has no additional fields. This is only used for testing block states, block models, and block textures.
Which means that this generator can not have a biome, so it is not of any use to us.

##### Flat {#flat}

The generator type used for superflat worlds.

This generator has the following JSON structure.

```Text
settings
├── layers : (required, but can be empty).
│   └── A layer
│       ├── height : the height of the layer.
│       └── block : (defaults to minecraft:air) the block ID.
├── biomes : (optional, defaults to `minecraft:plains`).
├── lakes : (optional, defaults to `false`).
├── features : (optional, defaults to `false`).
└── structure_overrides : (optional, defaults to all the structure set).
```

- **layers** :- This is a list that is read from top to bottom. Height is how many Y levels will the block span.
  - **_height_** :- The height of the layer. i.e, how many blocks tall the layer is.
  - **_block_** :- The block ID.

- **biomes** :- The ID of the single biome in the world. In this guide, the ID is `examplemod:tater_biome` for which we use `TATER_BIOME_KEY`.

- **lakes** :- Whether to generate lava lakes. If set to true, then lava lakes (lake_lava_underground and lake_lava_surface) generate even in biomes where lakes don't normally generate.

- **features** :- Whether to generate biome-specific placed features.

- **structure_override** :- List of structure sets to use. Can be an ID of structure set, a structure set tag, or a list of structure set IDs.

Here are the following changes that need to be made inorder to use the flat generator.

<!-- prettier-ignore -->
```java
    var biomeSource = new FixedBiomeSource(biomes.getOrThrow(TATER_BIOME_KEY)); // [!code --]

    ChunkGenerator chunkGenerator = new NoiseBasedChunkGenerator( // [!code --]
        biomeSource, // [!code --]
        noiseSettings.getOrThrow(NoiseGeneratorSettings.OVERWORLD) // [!code --]
    ); // [!code --]

    FlatLevelGeneratorSettings flatSettings = new FlatLevelGeneratorSettings( // [!code ++]
        Optional.empty(), // [!code ++]
        biomes.getOrThrow(TATER_BIOME_KEY), // [!code ++]
        List.of() // [!code ++]
    ); // [!code ++]

    flatSettings.getLayersInfo().add(new FlatLayerInfo(1, Blocks.BEDROCK)); // [!code ++]
    flatSettings.getLayersInfo().add(new FlatLayerInfo(63, Blocks.DIRT)); // [!code ++]
    flatSettings.updateLayers(); // [!code ++]
    ChunkGenerator chunkGenerator = new FlatLevelSource(flatSettings); // [!code ++]

    LevelStem exampleDimensionStem = new LevelStem(
        dimensionTypes.getOrThrow(ExampleModDimensionTypeProvider.EXAMPLE_DIMENSION_TYPE_KEY),
        chunkGenerator // [!code ++]
    );
```

Features and lakes can be added to the flat generator by using the `flatSettings.setDecoration();` and `flatSettings.setAddLakes();` methods respectively.

##### Noise {#noise-generator}

The generator used in all the default dimensions.

This generator has the following JSON structure.

```Text
generator
├── settings :- Settings for noise generator.
└── biome_source :- Settings determining the biome layout.
    └── type :- The biome source type as a resource location.
    └── additional fields
```

- **settings** :- Settings for the noise generator. One noise settings (an ID, or a new NBT compound tag noise settings definition).
- **biome_source** :- Settings determining the biome layout.
  - **_type_** :- The biome source type as a resource location.

The code shown earlier in [Advanced Configuration](#advanced-configuration) is an example of how to use the noise generator. It uses the default overworld noise settings and a fixed biome source.
So next on we are going to take a look at the available biome sources.

#### Biome Source {#biome-source}

The available candidates for the biome sources are Checkerboard, Fixed, Multi Noise and The End.

##### Checkerboard {#checkerboard}

The checkerboard biome source places biomes in a checkerboard pattern.

This biome source has the following JSON structure.

```Text
additional fields :
├── biomes :- Any number of biome(s).
└── scale :- (Optional, default is 2) Value between 0 and 62.
```

- **biomes** :- an ID, or a tag with #, or an array containing IDs.

- **scale** :- Determines the size of the checkerboard grid. A scale of 0 means each cell of the grid is one chunk wide. is Value^2 chunks.

Here are the following changes that need to be made inorder to use the checkerboard biome source.

<!-- prettier-ignore -->
```java
    var biomeSource = new FixedBiomeSource(biomes.getOrThrow(TATER_BIOME_KEY)); // [!code --]

    var biomeSource = new CheckerboardColumnBiomeSource( // [!code ++]
        HolderSet.direct(biomes.getOrThrow(TATER_BIOME_KEY), biomes.getOrThrow(Biomes.PLAINS)), // [!code ++]
        2 // Scale value between 0 and 62 // [!code ++]
    ); // [!code ++]

    ChunkGenerator chunkGenerator = new NoiseBasedChunkGenerator(
        biomeSource,
        noiseSettings.getOrThrow(NoiseGeneratorSettings.OVERWORLD)
    );

    LevelStem exampleDimensionStem = new LevelStem(
        dimensionTypes.getOrThrow(ExampleModDimensionTypeProvider.EXAMPLE_DIMENSION_TYPE_KEY),
        chunkGenerator
    );
```

The checkerboard biome source creates a pattern of biomes in a checkerboard layout.
In the example above, we have used `TATER_BIOME_KEY` and `Biomes.PLAINS` as the biomes with a scale of 2.
This means that the checkerboard pattern will have each biome take up a 4x4 chunk area.
You can adjust the scale and biomes as needed to create different patterns in your custom dimension. The code uses The Overworld Noise Settings.

##### Fixed {#fixed}

The fixed biome source, also called single biome, uses one specified biome everywhere.

This biome source has the following JSON structure.

```Text
additional fields :
└── biome :- One biome ID.
```

- **biome** :- The single biome to use.

The code shown at first in [Advanced Configuration](#advanced-configuration) is an example of how to use a fixed biome source with overworld noise settings.

##### Multi Noise {#multi-noise}

The multi-noise biome source places biomes using parameter points.

This biome source has the following JSON structure.

```Text
additional fields :
└── preset :- A reference to a parameter list.
or
└── biomes :- (Require atleast one entry) List of biome parameter point.
    └── A parameter point.
        ├── biome :- one biome ID.
        └── parameters :- the parameters of this entry.
```

- **preset** :- The default parameter lists are overworld and nether.

- **biomes** :- Biomes can appear in more than one parameter point.
  - **_biome_** :- The biome used at this parameter point.
  - **_parameters_** :- Noise parameter for the biome.

Here are the following changes that need to be made inorder to use the multi-noise biome source.

<!-- prettier-ignore -->
```java
    var biomeSource = new FixedBiomeSource(biomes.getOrThrow(TATER_BIOME_KEY)); // [!code --]

    var biomeSource = MultiNoiseBiomeSource.createFromList( // [!code ++]
        new Climate.ParameterList<>(List.of( // [!code ++]
            Pair.of(Climate.parameters(0.0F, 0.0F, 0.0F, 0.0F, 0.0F, 0.0F, 0.0F), biomes.getOrThrow(TATER_BIOME_KEY)), // [!code ++]
            Pair.of(Climate.parameters(0.0F, 1.0F, 0.0F, 0.0F, 0.0F, 0.0F, 0.0F), biomes.getOrThrow(Biomes.PLAINS)) // [!code ++]
        )) // [!code ++]
    ); // [!code ++]

    ChunkGenerator chunkGenerator = new NoiseBasedChunkGenerator(
        biomeSource,
        noiseSettings.getOrThrow(NoiseGeneratorSettings.OVERWORLD)
    );

    LevelStem exampleDimensionStem = new LevelStem(
        dimensionTypes.getOrThrow(ExampleModDimensionTypeProvider.EXAMPLE_DIMENSION_TYPE_KEY),
        chunkGenerator
    );
```

The method arguments are as follows:

- `float temperature`
- `float humidity`
- `float continentalness`
- `float erosion`
- `float depth`
- `float weirdness`
- `float offset`

To see how they affect the biome placement, you can see [World Generation](https://minecraft.wiki/w/World_generation#Biomes).

##### The End {#the-end}

The biome source used for the End dimension. This biome source has no additional fields. Therefore, it is not of any use to us.

### Noise Settings {#noise-settings}

This entire section is dedicated to the creation of a Noise Setting. This section is also entirely optional as you can easily use the existing Noise Settings such as `minecraft:overworld`, `minecraft:nether`, etc.

Before heading on lets first create the noise settings provider class with the bootstrap and fill out required details.

@[code lang=java transcludeWith=:::datagen-dimension:noiseSettingsProvider](@/reference/latest/src/client/java/com/example/docs/datagen/ExampleModNoiseSettingsProvider.java)

There are three major components of the Noise settings. These are :-

- **Noise** :- It contains fields such as `min_y`, `size_horizontal`, `size_vertical`, etc.
- **Noise Router** :- It routes density functions to noise parameters used for world generation.
- **Surface rules** :- It is a type of decision tree. Using a combination of sequences and conditions, it can implement checks to place the right blocks in the right places.

#### Noise {#noise}

It has the following JSON structure.

```Text
noise:
├── min_y:
├── height:
├── size_horizontal:
└── size_vertical:
```

- **min_y** : The minimum Y coordinate where terrain starts generating. Value between -2032 and 2031. Must be divisible by 16.
- **height** : The total height where terrain generates. Value between 0 and 4064. Must be divisible by 16. min_y + height cannot exceed 2032.
- **size_horizontal** : Value between 0 and 4. Note that the noise breaks into the 12×12 block section per chunk for the value 3.
- **size_vertical** : Value between 0 and 4.

Now let's start adding code to the bootstrap method.

@[code lang=java transcludeWith=:::datagen-dimension:customNoiseSettings](@/reference/latest/src/client/java/com/example/docs/datagen/ExampleModNoiseSettingsProvider.java)

Now you'll notice that `customNoiseRouter` and `customSurfaceRule` variables don't exist yet, so don't worry about that we are going to make
those variables in the next headings.

#### Noise Router {#noise-router}

As stated in the Minecraft Wiki,

> The noise router is a collection of density functions. Density functions compute a value for each block position. They are used for terrain generation, biome layout, aquifers, ore veins, and more. A noise router is a part of a dimension's noise settings.

It has the following JSON structure.

```Text
noise_router
├── preliminary_surface_level:
├── final_density:
├── barrier:
├── fluid_level_floodedness:
├── fluid_level_spread:
├── lava:
├── vein_toggle:
├── vein_ridged:
├── vein_gap:
├── temperature:
├── vegetation:
├── continents:
├── erosion:
├── depth:
└── ridges:
```

For the explanation of the above fields, you can refer to the [Noise Router](https://minecraft.wiki/w/Noise_router#JSON_format).

Now we will add the custom noise router in the bootstrap method.

@[code lang=java transcludeWith=:::datagen-dimension:noiseSettingsRouter](@/reference/latest/src/client/java/com/example/docs/datagen/ExampleModNoiseSettingsProvider.java)

Remember to add this above the `customNoiseSettings` variable not below!

#### Surface Rules {#surface-rules}

As stated in the Minecraft Wiki,

> A surface rule is a type of decision tree. Using a combination of sequences and conditions, it can implement checks to place the right blocks in the right places.

For every surface condition, you can refer to the [Surface Rule](https://minecraft.wiki/w/Surface_rule#JSON_format) and `net.minecraft.world.level.levelgen.SurfaceRules` class.

Now we will add the custom surface rule variable.

@[code lang=java transcludeWith=:::datagen-dimension:noiseSettingsSurfaceRule](@/reference/latest/src/client/java/com/example/docs/datagen/ExampleModNoiseSettingsProvider.java)

This surface rule does the following.

```Text
customSurfaceRule (SurfaceRules.sequence)
├── [IF] isBiome(TATER_BIOME)
│   │
│   ├── 1. [IF] Y >= 110 (Mountain Peak)
│   │   └── Block: CALCITE
│   │
│   ├── 2. [IF] steep()
│   │   └── Block: TUFF
│   │
│   ├── 3. [IF] ON_FLOOR (Surface Top Layer)
│   │   ├── [IF] waterBlockCheck(-1, 0) (Above Water)
│   │   │   ├── [IF] noise(SURFACE >= 0.2) ──PODZOL
│   │   │   ├── [IF] noise(GRAVEL >= 0.1) ──MOSS_BLOCK
│   │   │   └── [ELSE] ──GRASS_BLOCK
│   │   │
│   │   └── [ELSE] (Underwater Floor) ──MUD
│   │
│   └── 4. [IF] UNDER_FLOOR (Sub-surface Soil)
│       └── Block: PACKED_MUD
│
└──SurfaceRuleData.overworld()
    ├── Generates Bedrock floor (Y = -64)
    ├── Handles Deepslate transition (Y < 0)
    └── default surface rules for non-Tater biomes
```

Here is also an explanation using pure text:

```Text
1. Check if this is tater biome.
    1. If Y is greater than or equal to 110. Which are the mountain peaks. Place calcite block.
    2. If ON_FLOOR which means the top layer.
        1. If waterBlockCheck(-1, 0) which means above water.
            1. If surface noise condition is greater than or equal to 0.2. If true podzol block.
            2. If gravel noise condition is greater than or equal to 0.1. If true moss block.
            3. Else grass block.
        2. Else mud block.
    3. If under floor that is soil. Packed mud.
2. Else overworld surface data.
```

`/execute in <mod-id>:<dimension> run tp <username> ~ ~ ~`
